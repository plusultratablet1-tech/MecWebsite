# Deployment Guide

This guide covers deploying the Buildnox project to Vercel and GitHub.

## Prerequisites

- GitHub account (for version control)
- Vercel account (for hosting)
- Git installed locally
- Node.js 18+ and pnpm installed

## GitHub Setup

### Initial Push to GitHub

1. **Create a new repository on GitHub**
   - Go to [github.com/new](https://github.com/new)
   - Repository name: `buildnox` (or your preference)
   - Description: `Professional construction & architecture landing page`
   - Choose public or private
   - Do NOT initialize with README, .gitignore, or license

2. **Initialize local git repository**
   ```bash
   cd buildnox
   git init
   ```

3. **Add all files**
   ```bash
   git add .
   ```

4. **Create initial commit**
   ```bash
   git commit -m "feat: initial project setup with section-based architecture"
   ```

5. **Add remote repository**
   ```bash
   git remote add origin https://github.com/YOUR_USERNAME/buildnox.git
   git branch -M main
   git push -u origin main
   ```

### Branch Protection (Optional)

For production safety, add branch protection rules:

1. Go to Repository Settings → Branches
2. Add protection rule for `main` branch
3. Require pull request reviews
4. Require status checks to pass
5. Require branches to be up to date

## Vercel Deployment

### Option 1: Deploy via Dashboard (Recommended)

1. **Sign in to Vercel**
   - Go to [vercel.com](https://vercel.com)
   - Sign in with GitHub account

2. **Import Project**
   - Click "Add New..." → "Project"
   - Select "Import Git Repository"
   - Choose your GitHub repository
   - Click "Import"

3. **Configure Project**
   - Framework Preset: Next.js (auto-detected)
   - Root Directory: ./ (leave default)
   - Environment Variables: None required (optional)
   - Click "Deploy"

4. **Wait for Deployment**
   - Vercel will build and deploy your project
   - You'll see a live URL when complete

### Option 2: Deploy via Vercel CLI

1. **Install Vercel CLI**
   ```bash
   npm i -g vercel
   ```

2. **Authenticate**
   ```bash
   vercel login
   ```

3. **Deploy**
   ```bash
   vercel --prod
   ```

4. **Link to existing project (if re-deploying)**
   ```bash
   vercel --prod --yes
   ```

## Configuration

### Environment Variables

Set these in Vercel dashboard under "Settings" → "Environment Variables":

```
NEXT_PUBLIC_ANALYTICS_ID=your_analytics_id    (optional)
NEXT_PUBLIC_API_URL=https://your-domain.com
```

### Custom Domain

1. Go to Vercel Project Settings
2. Click "Domains"
3. Add your custom domain
4. Follow DNS configuration steps provided
5. DNS propagation usually takes 5-30 minutes

### SSL/TLS Certificate

- Automatically generated by Vercel for all deployed projects
- Free Let's Encrypt certificates
- Auto-renewal handled by Vercel

## Continuous Integration

GitHub Actions automatically runs on:

- Every push to `main` or `develop`
- Every pull request to `main` or `develop`

### Workflow Status

View CI status in:
- GitHub repository → "Actions" tab
- Pull requests → Checks section
- Commit history → Green/red checkmarks

### Workflow Steps

1. **Install Dependencies** - Installs pnpm and packages
2. **Type Check** - Runs TypeScript compiler
3. **Build** - Next.js production build
4. **Lint** - ESLint checks (if configured)

### Fixing CI Failures

1. Check the GitHub Actions log for errors
2. Fix issues locally and test
3. Commit and push
4. GitHub Actions automatically re-runs

## Rollback Strategy

If you need to revert a deployment:

1. **Via Vercel Dashboard**
   - Go to "Deployments"
   - Click on a previous deployment
   - Click "Promote to Production"

2. **Via Git**
   ```bash
   git revert <commit-hash>
   git push origin main
   ```

## Performance Tips

### Before Deployment

1. **Optimize images**
   - Compress images (use TinyPNG, ImageOptim)
   - Use modern formats (WebP, AVIF)
   - Set appropriate dimensions

2. **Check bundle size**
   ```bash
   pnpm build
   # Check .next/static/chunks for large files
   ```

3. **Performance testing**
   - Test on slow 3G in DevTools
   - Use Lighthouse audit
   - Check Core Web Vitals

### After Deployment

1. **Monitor Core Web Vitals**
   - LCP (Largest Contentful Paint)
   - FID (First Input Delay)
   - CLS (Cumulative Layout Shift)

2. **Check Vercel Analytics**
   - Real user metrics
   - Deployment comparison
   - Performance timeline

## Troubleshooting

### Build Fails

1. Check build logs in Vercel dashboard
2. Run `pnpm build` locally to reproduce
3. Common issues:
   - Missing environment variables
   - Incompatible Node version
   - Missing dependencies

### Slow Performance

1. Analyze bundle size
2. Check image optimization
3. Review database queries
4. Use Lighthouse DevTools

### Images Not Loading

1. Verify image paths (use `/images/filename`)
2. Check public folder structure
3. Ensure images are committed to git
4. Clear Vercel cache and redeploy

### DNS Issues

1. Verify DNS records in domain registrar
2. Check Vercel domain settings
3. Wait for DNS propagation (up to 48 hours)
4. Use DNS checker tools

## Deployment Timeline

Typical deployment workflow:

1. **Local Development** (your machine)
   - Code changes
   - Local testing
   - Commit to git

2. **GitHub** (5 seconds)
   - Push changes
   - GitHub Actions CI runs
   - Checks pass/fail

3. **Vercel** (1-2 minutes)
   - Automatic deployment triggered
   - Build process runs
   - Live at your domain

Total time: ~2-3 minutes from push to live
